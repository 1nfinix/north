# SQL 评审

## 何时使用

审查查询、写入、迁移或 ORM 生成的 SQL，且需要判断结果、性能或并发风险时使用。先确认数据库引擎、版本、表结构和数据规模；未给出的信息列为待确认。

## 分步流程

1. 读取目标 SQL、调用代码、参数来源及 schema；记录预期行集合、排序、事务范围和错误处理。
2. 在 PowerShell 或 Git Bash 中可运行以下仓库检查命令；将路径换为目标文件。不要直接在生产库执行评审用 SQL：

   ```text
   git status --short
   git diff -- path/to/query.sql
   git grep -n 'table_name'
   ```

3. 用小型、脱敏的数据集检查 NULL、重复行、空集合、时区、分页边界及 JOIN 基数。写入语句还需检查重试和幂等性。
4. 检查参数绑定：表名或排序字段等无法参数化的部分必须来自明确白名单，不能拼接任意用户输入。
5. 在已获准的开发或测试库读取执行计划。示例：`EXPLAIN SELECT ...;`；实际语法、是否需要 `ANALYZE` 及是否会执行写入，均以数据库文档为准。
6. 比对过滤、连接、排序与索引；关注全表扫描、重复扫描、隐式转换和大 OFFSET。分析写入锁顺序、事务时长及隔离级别。
7. 提供可验证的修改建议和测试 SQL；若缺表统计或执行计划，报告假设，不宣称性能改善已证实。

## 检查清单

- [ ] 数据库引擎、版本及预期结果明确。
- [ ] JOIN 条件与基数不会意外放大或丢失行。
- [ ] NULL、重复值、空输入和排序稳定性已检查。
- [ ] 外部输入使用绑定参数或受控白名单。
- [ ] 过滤、连接、排序列与索引和执行计划相符。
- [ ] 大结果集、分页和聚合的资源成本已估计。
- [ ] 写操作的锁、事务、重试和幂等性已考虑。
- [ ] 评审命令只在授权环境运行，不泄露真实数据。

## 输出格式

```markdown
## SQL 结论
- 严重程度：
- 位置：`path/to/file:line`
- 触发条件与影响：
- 证据：样例结果或执行计划摘要
- 建议：SQL 或索引修改及验证方法

## 验证范围
- 已运行：命令、数据库环境和结果
- 待确认：统计信息、并发条件或真实数据规模
```

## 常见陷阱

- 只凭索引存在就断言查询会使用它。
- 在生产库运行会改变数据的 `EXPLAIN ANALYZE` 或迁移试验。
- 忽略 NULL 语义、隐式类型转换和并发写入。
