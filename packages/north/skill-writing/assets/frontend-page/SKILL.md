# 网页制作

## 先确认

- 页面给谁看、主要用途（介绍、汇报、看数据、填写或计算），以及要放的真实内容。缺少内容时先提出一版文案方案并说明是草稿，不编造数据。
- 用户已经指定风格、配色或参考页面时，严格照做；没有指定时由你提出方向。
- 判断页面类型，决定用力的地方：
  - **实用页**（通知、说明、汇报材料）：讲究层级、间距和配色，不做大幅首屏和装饰。
  - **展示页**（活动页、宣传页、会被保存和转发的页面）：在一处做有主见的设计。
  - **看板和工具**：重点是信息组织，先给汇总，再给明细；打开就显示真实数据，不是空的待操作状态。

  拿不准时，排版整齐的朴素页面总比过度设计稳妥。

## 定视觉方向（先计划，再写代码）

写代码之前，先给出一份简短的设计计划：

- **配色**：4–6 个带名字的颜色值。灰色带一点主色的色相；表示好、警告、严重的颜色与强调色分开。
- **字体**：用系统字体栈，例如 `"Microsoft YaHei", "PingFang SC", "Noto Sans CJK SC", sans-serif`，标题可选宋体类 `"SimSun", "Songti SC", serif` 做对比；最多两种字体，不引用网络字体。
- **布局**：一句话说明布局思路，必要时画 ASCII 草图；说明内容左对齐还是居中。
- **原则**：这个页面区别于普通模板的一两点。

然后对照需求检查：如果某一部分换个主题也会得出同样的结果，说明它是默认套路而不是选择，改掉它并说明原因。风格从页面主题所在的行业、材料和用语中来。

常见的生成套路（除非需求明确要求，否则避免）：

- 米色背景配高对比衬线标题和陶土色强调色；或近黑背景配一个荧光绿、朱红强调色。
- 所有内容切成同样圆角、同样阴影的卡片，用渐变做装饰。
- 每个标题上方都有全大写的小标签；只把标题中的一个词换颜色或加粗；按钮文字后面都加「→」。
- 内容并不是步骤或时间线，却加上 01 / 02 / 03 编号。
- 每个区块都做淡入上移动画，每张卡片都有悬停动效。
- 用 emoji 当小节标记；所有内容居中；紫到蓝的渐变首屏。
- 文案套路：破折号插入语、「不是……而是……」、冒号后揭晓答案。

## 写法

- 首屏放这个主题最有代表性的内容：一句标题、一个关键数字、一个可操作的示例，按内容选择，不要默认套用「大数字＋小标签＋渐变」。首屏高度随内容，不用 `100vh`；打开页面时要读的内容都已显示，不停在 `opacity: 0` 等滚动或点击触发。
- 把大胆用在一处：一个让人记住的元素，其余保持安静、整齐，删掉不服务内容的装饰。
- 正文每行不超过约 40 个汉字，设定清晰的字号层级并全页遵守。标题加 `text-wrap: balance`；需要对齐的数字列用 `font-variant-numeric: tabular-nums`。
- 结构元素（边框、分隔线、编号、标签）只在传达信息时使用；边框、阴影、圆角只给真正需要突出的元素。
- 布局：同级元素用 flex 或 grid 的 `gap` 排间距；任何宽度下左右至少留 16px，手机宽度改单栏；页面本身不横向滚动，宽表格、代码放进自己的 `overflow-x: auto` 容器；图片 `max-width: 100%`；文字超长时换行，不能被截断。
- 动效克制：最多一个页面加载或展开时刻；响应用户操作的动效可以有。
- 文案从使用者角度写，用主动语态；按钮写清楚会发生什么（「保存修改」而不是「提交」），同一个操作在整个流程中名称一致；报错说明出了什么问题以及怎么解决。
- 质量底线：适配手机宽度、键盘焦点可见、尊重「减少动态效果」设置、文字与背景对比足够。
- CSS 注意选择器优先级，避免类名之间的内外边距互相覆盖。

## 技术要求

- 交付单个 `.html` 文件，样式和脚本内联；不引用 CDN、网络字体或外网图片，内网电脑可能无法联网。图片用工作区里的本地文件。
- `<title>` 写一个简短具体的页面名称，不加破折号或冒号说明。
- 颜色写成 `<style>` 顶部 `:root` 里的变量，页面各处只用变量取色，`body` 明确设置背景色。只做浅色版时把所有颜色都写明；同时做深色版时，在 `@media (prefers-color-scheme: dark)` 里重新定义同一组变量并设 `color-scheme: dark`，不要简单反色，也不要漏定义某个颜色导致深色下看不清。
- 一屏应用用 `html, body { height: 100%; }`，不用 `100vh`；浏览器存储读写包在 `try/catch` 里，只存个人偏好。
- 页面里需要图表时，加载 `chart` 技能制作。

## 自检与交付

1. 加载 `browser-check`，用本地临时服务打开页面，在 1280×800 和 390×844 两种宽度下各截图一次。
2. 按 `browser-check` 的方法检查文字溢出、横向滚动、遮挡、空白区域、对比度和控制台报错；当前模型不能查看图片时，用页面结构和脚本检查代替看图，并请用户打开截图确认。
3. 再对照：首屏内容完整、没有占位文案、做了深色版时两种配色都看得清、没有落入上面的常见套路；最后删掉一处不服务内容的装饰。按发现的问题改一轮，再检查一次，不反复循环。
4. 用 `present` 交付 HTML 文件，附一两句话说明设计方向和需要用户补充的内容。
