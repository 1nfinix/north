# 接口文档

## 何时使用

新增或变更 HTTP、RPC 或 SDK 接口，需要让调用者知道可用的路径、字段、错误和兼容性时使用。以当前代码和可运行测试为依据，明确未验证的运行环境。

## 分步流程

1. 确定目标接口和版本，阅读路由注册、处理器、类型定义、认证中间件及相关测试；别只复制旧文档。
2. 以下命令在 PowerShell 和 Git Bash 均可运行；替换示例路径或符号：

   ```text
   git status --short
   git grep -n 'routeName'
   git diff -- path/to/handler
   ```

3. 逐项提取方法与路径、请求头、路径/查询/正文参数、默认值、校验限制、成功响应和错误状态。区分必填、可选与可空。
4. 查找权限、速率限制、分页、排序、幂等性和版本兼容约束。对每种响应写明触发条件，不自行发明未实现的状态码。
5. 选择仓库已有的 Markdown 或 OpenAPI 形式。示例使用虚构数据；若需 HTTP 示例，可用 `https://example.com/api/items`，不能粘贴真实令牌。
6. 运行仓库现有文档或 schema 校验命令，并与相关测试对照。若接口需要真实服务才能确认，标记为未验证。

## 检查清单

- [ ] 方法、路径和版本与实际注册一致。
- [ ] 认证、权限和必要请求头明确。
- [ ] 所有输入字段写明类型、必填性与约束。
- [ ] 成功响应字段及可空性与代码一致。
- [ ] 错误状态、错误体和触发条件可追溯。
- [ ] 分页、排序和幂等性约定有据可查。
- [ ] 示例使用虚构值，不含密钥或真实人员信息。
- [ ] 文档校验与接口测试的实际结果已记录。

## 输出格式

```markdown
## 接口：`METHOD /path`
- 用途：
- 认证：
- 请求：字段、类型、必填性、约束
- 成功响应：状态与字段
- 错误：状态、条件与字段
- 示例：使用虚构值的请求与响应

## 验证
- 来源：实现和测试路径
- 已运行：`命令` → 结果
- 未验证：环境或行为
```

## 常见陷阱

- 把 TypeScript 可选字段误写成运行时一定接受。
- 漏掉中间件上的认证或隐藏在公共解析器中的校验。
- 将示例响应当作所有错误路径的保证。
