# 陌生代码解读

## 何时使用

接手一个模块、排查调用路径或需要向同伴解释某项行为时使用。先限定问题：某个命令、页面、接口或文件的哪种行为；不要从目录名推断运行时关系。

## 分步流程

1. 阅读仓库入口文档和目标目录说明，确认使用的语言、构建入口及运行配置。记录所看的提交或工作区状态。
2. 以下通用命令可在 PowerShell 与 Git Bash 运行；将示例符号换成真实名称：

   ```text
   git status --short
   git grep -n 'functionName'
   git grep -n 'configKey'
   git log -5 --oneline -- path/to/file
   ```

3. 从实际入口（CLI、路由、事件、插件注册或导出）开始，沿调用链找到负责该行为的模块；区分静态导入与运行时装载。
4. 对一个代表性请求追踪输入来源、校验、状态变化、持久化和输出。标出失败分支、异步任务及释放点。
5. 用调用者、测试或最小运行命令验证关键结论。若依赖构建产物，确认源码与产物版本一致，不把注释当运行证据。
6. 画出简短模块关系或调用顺序，给每条重要关系附文件路径或符号名；列出未知点及下一步验证方法。

## 检查清单

- [ ] 目标行为和代码版本明确。
- [ ] 入口由实际注册、导出或调用证明。
- [ ] 模块关系区分依赖、调用与数据传递。
- [ ] 输入格式、校验和默认值已定位。
- [ ] 状态和持久化的写入者、读取者已定位。
- [ ] 错误、取消和资源清理路径有说明。
- [ ] 关键结论有文件或测试证据。
- [ ] 不确定的动态装载或环境依赖被明确标记。

## 输出格式

```markdown
## 目标与入口
- 行为：
- 入口：`path/to/file` / `symbol`

## 模块关系
- A → B：调用或数据，证据位置

## 数据流
1. 输入与校验
2. 状态变化
3. 输出与失败路径

## 已验证与待确认
- 验证：`命令` → 结果
- 待确认：具体问题和验证方法
```

## 常见陷阱

- 把 README 中的设计意图当成当前运行事实。
- 只顺着 import 看依赖，却漏掉注册、反射和配置驱动装载。
- 用过长的文件清单替代关键数据流说明。
